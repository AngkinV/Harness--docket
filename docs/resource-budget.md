# 低内存、低 CPU/GPU、低存储规则

功能正确与资源预算同时验收。规则不代表所有设备已经达标；未测量的平台和指标必须标记未验证。

## 设计边界

- 资源按需加载；默认一个人物，切换临时资源在成功、失败、取消、卸载时完整释放。
- GPU uniform 贴图、共享纹理、ImageBitmap、几何、骨骼、mixer、渲染器、视频解码器、object URL、Worker、observer、监听器、定时器和网络请求均需释放。
- 默认绘制最高 30fps，DPR 不超过 1.5；静止且无视觉变化时按需绘制。后台停止装饰绘制、视频与轮廓采样。
- 轮廓采样 3D 最高 5Hz、透明视频最高 4Hz，最多一个待完成 GPU 读回。
- 新增默认模型贴图的 RGBA8 基础数据合计不超过 64 MiB，优先最长边不超过 1024。原始用户素材不静默改写，派生资源另存。
- 动作轨道缓存同时不超过 64 MiB 和 12 项。缓存、队列、并发均设上限、淘汰和取消策略。
- 同一视图最多一个模型解析任务；浏览器解析 Worker 与服务端资源校验各最多两个，队列最多 16 项。
- 透明角色稳定态一路播放，切换最多两路，提交后释放旧解码器；封面抽帧并发最多两个，结束释放媒体源。
- 禁止无界缓存、并发、日志、轮询；优先事件驱动，轮询须有退避与卸载取消。

## 验收

文档及不影响运行资源的发布工具改动无需重跑完整渲染性能测试。涉及渲染、媒体、缓存或生命周期的变更：

1. 使用同一设备、浏览器、视口、DPR、模型/动作、片库规模，对比无插件/关闭人物、修改前、修改后。预热 30 秒，前台采样至少 60 秒、后台至少 30 秒。
2. 记录 JS heap、页面/宿主 RSS、可取得的 GPU 计数、CPU、实际绘制与采样频率。共享 GPU 进程不能算成插件独占内存。
3. 至少十轮打开/关闭、模型切换、播放/停止，加入快速取消、失败和后台恢复。每轮结束等五秒，前后使用相同 GC 方法。GPU、媒体、Worker 和监听器不得逐轮增加。
4. 十轮稳定 heap 增量不超过 max(10 MiB, 基线的 5%)，后五轮不得持续增长；稳定内存回归不超过 max(10 MiB, 10%)，CPU 不得无解释增加超过单核口径两个百分点。
5. 轻量默认场景以插件相对基线 CPU 均值不超过单核 5%、每帧 JS p95 不超过 5ms 为目标。持续增长缺陷未修复不能交付，不可静默放宽阈值。

## 测试、存储与清理

每次测试使用独立 run-id、实例与浏览器目录，记录自建进程 PID 和完成状态，失败也必须结束进程。浏览器设置磁盘缓存 64 MiB、媒体缓存 32 MiB；退出后仍检查组件缓存。不使用全局 killall，不清理用户浏览器或实例数据。

删除前检查测试已结束、进程不存在、文件未占用，只清理已知可重建文件。原始素材、用户配置、上传、会话、数据库和历史交付包不属于缓存。禁止整删 .work，禁止把缓存移到项目外冒充清理。

已完成测试缓存合计不超过 256 MiB，任务结束应清空；.work 目标不超过 1 GiB，artifacts 目标不超过 512 MiB。新增测试证据原则上不超过 50 MiB。0.9.2 四条指定原画片头版经维护者要求扩大体积预算：安装包压缩不超过64 MiB、解包不超过80 MiB，公开树不超过100 MiB；仅固定哈希的光影·动色允许20,375,525字节。其他媒体仍不超过5 MiB。运行资源门槛不变。内嵌视频解码缓存最多一条/24 MiB，30秒空闲或卸载清除；Node的固定ESM/base64模块仍保留，不宣称完全卸载。依赖按需复用，构建临时目录必须在 finally 中清理。

验证记录仅存本地，记录适用边界、前后测量、生命周期、体积、清理文件数/字节数与未解决问题；按发布规则禁止将这些记录上传公开仓库。
